# Практическая работа 4.2 — ГОСТ Р 34.10-2012, 256 бит

Реализованы генерация ключей, подпись произвольного файла и проверка сохранённой подписи.

```powershell
[IO.File]::WriteAllText('signed-message.txt', 'Пример электронной подписи', [Text.UTF8Encoding]::new($false))
go run ./GOSTSignature keygen -private gost-private.json -public gost-public.json
go run ./GOSTSignature sign -in signed-message.txt -key gost-private.json -out message.sig
go run ./GOSTSignature verify -in signed-message.txt -key gost-public.json -sig message.sig
go test ./internal/gostsign ./GOSTSignature
```

Проверка выводит `OK`. Случайные ключи и подписи меняются при каждом запуске. Внутри папки работы используйте `go run .`. Подмена файла обнаруживается:

```powershell
[IO.File]::AppendAllText('signed-message.txt', '!')
go run ./GOSTSignature verify -in signed-message.txt -key gost-public.json -sig message.sig
# Ошибка проверки, ненулевой код завершения.
```

Секрет d и одноразовое число k независимо выбираются из 1…q−1 с помощью `crypto/rand` и rejection sampling. Вычисляются Q=dP, e=α mod q (при нуле e=1), C=kP, r=x(C) mod q, s=(rd+ke) mod q; нулевые r/s требуют нового k. При проверке v=e⁻¹ mod q, z1=sv mod q, z2=−rv mod q; подпись верна, когда x(z1P+z2Q) mod q=r. Проверяются диапазоны 0<r,s<q и принадлежность открытой точки кривой и подгруппе q; бесконечная точка запрещена.

α — целое из 32 байтов Стрибога в **little-endian**: первый байт обычного файлового дайджеста — младший. Подпись — ровно 64 **двоичных** байта: `r || s`, каждое число по 32 байта **big-endian** с ведущими нулями. Это явно выбранный учебный формат, не контейнер ASN.1, CMS или формат стороннего криптопровайдера.

Ключи — UTF-8 JSON с идентификатором `gost3410-2012-256-rfc7091-test`. Секретный ключ: `{"algorithm":"gost3410-2012-256-rfc7091-test","d":"<64 hex-цифры>"}`. Открытый: `{"algorithm":"gost3410-2012-256-rfc7091-test","x":"<64 hex-цифры>","y":"<64 hex-цифры>"}`. Числа в JSON представлены big-endian hex, допускается верхний регистр. Неизвестные поля/алгоритмы, лишние JSON-значения и неверные длины отвергаются. Файлы ключей и подписи ограничены по размеру при чтении. Выходные файлы создаются исключительно заново; коллизия имени, в том числе с входом, завершается ошибкой.

Закрытый ключ хранится открытым текстом без шифрования. Повторное использование k раскрывает d; заменять случайность константой нельзя. Реализация на `math/big` не обеспечивает постоянное время, защиты памяти и сертификации. Данные файла читаются целиком в память. Фиксированный тест RFC проверяет публичную точку и r/s независимо от собственного хэширования; отдельно тестируется сквозная подпись двоичных/UTF-8 данных и отказ при подмене.
