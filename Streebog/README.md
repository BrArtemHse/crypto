# Практическая работа 3.2 — Стрибог-256

```powershell
# Файл без BOM и перевода строки, ровно 63 ASCII-байта.
[IO.File]::WriteAllText('message.txt', '012345678901234567890123456789012345678901234567890123456789012', [Text.UTF8Encoding]::new($false))
go run ./Streebog hash -in message.txt
go run ./Streebog hash -in message.txt -out message.streebog
go run ./Streebog check -in message.txt -hash message.streebog
go test ./internal/streebog ./Streebog
```

Ожидаемый хэш: `9d151eefd8590b89daa6ba6cb74af9275dd051026bb149a452fd84e5e57b5500`. Успешная проверка выводит `OK`; несовпадение, повреждённая запись или ошибка аргументов завершаются с ненулевым кодом. Чтобы проверить обнаружение изменения:

```powershell
[IO.File]::AppendAllText('message.txt', '!')
go run ./Streebog check -in message.txt -hash message.streebog
# Ошибка: хэш не совпадает; ненулевой код завершения.
```

Вход — точные байты файла, включая нули, BOM и переводы строк. Текст не перекодируется. Файл результата содержит 64 строчные hex-цифры и LF; при чтении допускаются окружающие пробельные символы и верхний регистр hex. Другие данные отвергаются. Отображается обычный порядок байтов файлового дайджеста, совпадающий с контрольными векторами Botan/Linux. RFC 6986 записывает векторы старшими байтами слева: для сопоставления его примеров обращаются байты и сообщения, и итогового хэша. Например, записанный в RFC результат `00557b...1e159d` превращается в приведённый выше `9d151e...7b5500`. Это преобразование относится только к чтению примера стандарта: программа не обращает содержимое файла пользователя.

Существующий выходной файл никогда не перезаписывается; для повторного опыта выберите новое имя. Данные читаются целиком в память, поэтому реализация рассчитана на учебные файлы. Поддерживаются пустой файл и размеры, кратные 64 байтам: даже после полного блока добавляется отдельный блок дополнения. Хэш позволяет обнаружить изменение при наличии доверенного эталона; сам файл хэша не подтверждает автора.
