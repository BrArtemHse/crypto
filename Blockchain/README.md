# Практическая работа 5 — учебный блокчейн

Собственные реализации Стрибога-256, генератора псевдослучайных чисел, подписи Шнорра key-prefixed, дерева Меркла и поиска nonce.

## Запуск

Команды выполняются из корня репозитория. Из этой папки замените `go run ./Blockchain` на `go run .`.

```powershell
go run ./Blockchain generate --name 'Иванов Иван' --out results/block --time '2026-10-27T12:00:00+03:00'
go run ./Blockchain verify --dir results/block
go test ./internal/blockchain ./Blockchain
```

Вместо примерного имени передайте собственные фамилию и имя. При одинаковых имени и времени результат воспроизводим. Без `--time` берётся текущее время компьютера. Выходная папка блока должна отсутствовать; её родительские каталоги создаются автоматически. Повторный запуск требует другого `--out`.

Для приведённого имени и времени результат:

```text
Merkle root: a2ab9f32259641c5a2b66f91ff61386c177944e96b8d3bc09670e5667e531a2c
Nonce: 7
Block hash: 074f1b359e61dcbac991e3aae1891cb1bd1d310853ab2fdc254a5c0cd61d8d00
```

Генерация создаёт пять файлов `tx01.bin`…`tx05.bin` по **200 байт**, пять подписей `tx01.sig`…`tx05.sig` по **96 байт** и `block.json`. В первой транзакции записано имя UTF-8, остальные байты получены из ГПСЧ. JSON содержит версию формата, открытый ключ, 76-байтовый заголовок и его хэш в hex. Секретный ключ и нонсы не сохраняются. Проверяющая команда читает фактические файлы, проверяет все подписи, заново строит дерево, сверяет корень и проверяет доказательство работы. Успех — `OK`, ошибка — ненулевой код завершения.

```powershell
# Пример обнаружения подмены после генерации:
$path = 'results/block/tx01.bin'
$data = [IO.File]::ReadAllBytes($path)
$data[199] = $data[199] -bxor 1
[IO.File]::WriteAllBytes($path, $data)
go run ./Blockchain verify --dir results/block
# Проверка завершается ошибкой.
```

## Генератор

Имя занимает от 1 до 64 байт UTF-8; оно дополняется нулевыми байтами справа до 64 байт. `h0=H(seed64)`. Далее `hi=H(h0||i)`, i начинается с 1, счётчик кодируется **32 байтами big-endian**. Поэтому каждый вход H имеет ровно 512 бит, выход — 256 бит. Неиспользованный остаток очередного блока сохраняется в буфере, выдаваемые байты не повторяются и не отбрасываются при смене размера чтения.

Числа ключа x и нонсов r выбираются rejection sampling из диапазона 1…q−1, без смещения от простого взятия остатка. Для пяти подписей дополнительно контролируется различие нонсов. Предыдущий хэш блока также получает 32 байта из этого потока.

## Подписи

Параметры p (512 бит), q (256 бит), g взяты **именно из приложения А.3 ГОСТ Р 34.10-94**, где g обозначен a. В коде проверяются простота p,q, делимость p−1 на q, диапазон g и равенство g^q mod p=1. Это параметры группы; сам алгоритм подписи здесь — Шнорр из задания, а не ГОСТ Р 34.10-94.

Открытый ключ P=g^x mod p. Для сообщения m выбирается новый r, вычисляются R=g^r mod p, e=H(R||P||m) mod q и s=(r+ex) mod q. При проверке должно выполняться g^s=R·P^e mod p. P и R кодируются ровно 64 байтами big-endian, e интерпретируется как big-endian целое. Подпись — `R[64]||s[32]`, числа big-endian с ведущими нулями. Проверяются длины, диапазоны и принадлежность R,P подгруппе; единичный элемент как ключ или R отвергается.

## Дерево Меркла

Лист — `H(tx[200]||signature[96])`; подпись включена в дерево вместе с транзакцией. Внутренний узел — `H(left[32]||right[32])`. На каждом уровне нечётный последний узел дублируется. Для пяти листьев число узлов на уровнях составляет 5 → 3 → 2 → 1. Один лист сам является корнем. Порядок файлов фиксирован от 01 до 05.

## Заголовок и поиск nonce

| Смещение | Длина | Содержимое |
|---|---:|---|
| 0 | 4 | Произвольные ненулевые байты поля размера, как требует задание |
| 4 | 32 | Предыдущий хэш из учебного ГПСЧ |
| 36 | 32 | Корень дерева Меркла |
| 68 | 4 | Час, день, месяц, год mod 100 |
| 72 | 4 | Nonce, uint32 big-endian |

Поле размера по условию содержит произвольные ненулевые байты и не кодирует фактический размер файла. Счётчик nonce начинается с нуля. Ищется H(header), у которого пять **старших** бит первого байта нулевые: `hash[0] & 0xf8 == 0`. Вероятность успеха одной попытки 1/32, среднее число попыток 32; конкретное число зависит от данных. При исчерпании uint32 возвращается ошибка.
