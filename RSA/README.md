# Практическая работа 4.1 — RSA и атака Ферма

```powershell
go test ./internal/rsalab ./RSA
go run ./RSA keygen --bits 2048 --public rsa-public.json --private rsa-private.json
[IO.File]::WriteAllBytes((Join-Path $PWD "rsa-input.bin"), [byte[]](0, 0, 255, 65, 66, 0))
go run ./RSA encrypt --key rsa-public.json --in rsa-input.bin --out rsa-encrypted.bin
go run ./RSA decrypt --key rsa-private.json --in rsa-encrypted.bin --out rsa-restored.bin
[BitConverter]::ToString([IO.File]::ReadAllBytes((Join-Path $PWD "rsa-restored.bin"))).Replace("-", "")
```

Ожидаемый результат: `0000FF414200`. Для повторного запуска выбирайте новые
имена: существующие выходные файлы, включая входной, не перезаписываются.
Генерация двух ключевых файлов предварительно резервирует оба имени и при
ошибке не оставляет частично созданную пару. Закрытые ключи записываются с
режимом `0600` (реальные права доступа Windows зависят от ACL).

Для различных нечётных простых p,q вычисляются n=pq, φ=(p−1)(q−1),
выбирается 1<e<φ с НОД(e,φ)=1, затем d=e⁻¹ mod φ. Шифрование числа:
c=mᵉ mod n, расшифрование m=cᵈ mod n, 0≤m,c<n. При случайной генерации
используется e=65537, допустимые размеры модуля — 32…8192 бит. Параметры
малых учебных примеров можно задать явно через `--p`, `--q`, `--e`.

## Три ручных примера

1. p=61, q=53: n=3233, φ=3120, e=17, d=2753, поскольку
   17·2753=46801=15·3120+1. Для m=65 получаем последовательно
   65² mod n=992, 65⁴ mod n=1232, 65⁸ mod n=1547,
   65¹⁶ mod n=789. Поэтому c=789·65 mod 3233=2790;
   2790²⁷⁵³ mod 3233=65.
2. p=11, q=13: n=143, φ=120, e=7, d=103, поскольку
   7·103=721=6·120+1. Для m=42: 42² mod143=48,
   42⁴ mod143=16, c=16·48·42 mod143=81;
   81¹⁰³ mod143=42.
3. p=17, q=19: n=323, φ=288, e=5, d=173, поскольку
   5·173=865=3·288+1. Для m=42: 42² mod323=149,
   42⁴ mod323=237, c=237·42 mod323=264;
   264¹⁷³ mod323=42.

```powershell
go run ./RSA number --p 61 --q 53 --e 17 --message 65
go run ./RSA number --p 11 --q 13 --e 7 --message 42
go run ./RSA number --p 17 --q 19 --e 5 --message 42
```

Каждая команда печатает n, φ, e, d, m, c и восстановленное m. Совпадение с
ручными значениями проверяется также тестами. Модуль 143 допустим для чисел,
но слишком мал для файлового кодирования, которому требуется n≥256.

Для последовательностей символов при p=61, q=53, e=17, d=2753 каждый
ASCII-байт является отдельным открытым блоком (b=1). Получаются три примера:

| Текст | ASCII-байты m | Шифроблоки m¹⁷ mod3233 | После c²⁷⁵³ mod3233 |
|---|---|---|---|
| `AB` | 65, 66 | 2790, 524 | 65, 66 → `AB` |
| `Go` | 71, 111 | 669, 2185 | 71, 111 → `Go` |
| `Hi` | 72, 105 | 3000, 3179 | 72, 105 → `Hi` |

Каждую степень можно вычислить вручную последовательным возведением в квадрат,
как для m=65 выше. Например, для m=66 остатки степеней 2, 4, 8 и 16 равны
1123, 259, 2421 и 3045; 3045·66 mod3233=524. Программа `number --p 61 --q 53
--e 17 --message 66` даёт те же 524 и восстановленное 66. Все три строки
также проверены файловыми командами encrypt/decrypt с этим малым ключом;
после 20-байтового заголовка каждое приведённое c записывается двумя байтами
big-endian. Для воспроизведения создайте файл с точными ASCII-байтами без BOM
и перевода строки и используйте файловые команды из первого примера.

## Криптоанализ

```powershell
go run ./RSA keygen --p 61 --q 53 --e 17 --public rsa-small-public.json --private rsa-small-private.json
go run ./RSA attack --key rsa-small-public.json --iterations 100 --out rsa-recovered.json
```

Атака Ферма перебирает A от ceil(√n), проверяя, является ли A²−n квадратом
B². Тогда p=A−B, q=A+B. Для 3233 сразу A=57,
57²−3233=16=4², поэтому p=53, q=61, d=2753: проверен один кандидат.
Для 143: A=12, B=1; для 323: A=18, B=1. Если p и q далеко друг от друга,
число шагов может быть огромным. Команда имеет обязательный положительный
предел от 1 до 10000000, по умолчанию 100000 кандидатов; по исчерпании возвращает ошибку.
Большие случайные ключи в общем случае этим методом практически не вскрываются.

## Форматы и ограничения

Открытый ключ JSON: `{"version":1,"n":"3233","e":"17"}`.
Закрытый дополнительно содержит десятичные строки `d`, `p`, `q`.
Неизвестные и повторяющиеся поля, лишние JSON-значения, неподходящие диапазоны, составные
множители, несовпадение n и неверное d отвергаются.

Контейнер начинается с 8 байт ASCII `RSALAB01`, далее 4 байта длины
шифроблока k=ceil(bitlen(n)/8) и 8 байт исходной длины (целые big-endian).
Каждый шифроблок занимает ровно k байт. Открытый блок имеет
b=floor((bitlen(n)−1)/8) байт, поэтому гарантированно меньше n.
Последний открытый блок имеет фактическую оставшуюся длину. При
расшифровании ведущие нули каждого блока восстанавливаются по известной
длине. Пустой файл содержит только 20-байтовый заголовок. Длина контейнера
проверяется до выделения памяти; блоки c≥n и восстановленные значения,
не помещающиеся в соответствующее число байт, отвергаются.
