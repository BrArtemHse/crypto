# Практическая работа 3.1 — AES-128

Реализация AES-128.

```powershell
go test ./internal/aes128 ./AES
[IO.File]::WriteAllBytes((Join-Path $PWD "aes-input.bin"), [byte[]](0, 0, 255, 65, 66, 0))
go run ./AES encrypt --key 000102030405060708090a0b0c0d0e0f --in aes-input.bin --out aes-encrypted.bin
go run ./AES decrypt --key 000102030405060708090a0b0c0d0e0f --in aes-encrypted.bin --out aes-restored.bin
[BitConverter]::ToString([IO.File]::ReadAllBytes((Join-Path $PWD "aes-restored.bin"))).Replace("-", "")
```

Последняя команда выводит `0000FF414200`. Для запуска из папки работы
используйте `go run .` вместо `go run ./AES`. Выходные файлы должны
отсутствовать: программа отказывает в перезаписи, в том числе входного файла.
Повторный запуск примера требует новых имён выходных файлов.

AES обрабатывает блок из 16 байт, расположенных столбцами в матрице 4×4.
128-битный ключ разворачивается в 11 раундовых ключей. После начального
AddRoundKey выполняются девять раундов SubBytes (нелинейная подстановка),
ShiftRows (циклический сдвиг строк), MixColumns (линейное преобразование
столбцов над GF(2⁸)) и AddRoundKey (XOR с раундовым ключом). В десятом раунде
MixColumns отсутствует. Обратные преобразования восстанавливают блок.
Умножение в GF(2⁸) использует многочлен x⁸+x⁴+x³+x+1 (`0x11b`).

В CBC перед шифрованием блок XOR-ится с предыдущим шифроблоком, первый —
со случайным IV из системного криптографического источника. PKCS#7 всегда
добавляет от 1 до 16 байт, каждый равен числу добавленных байт. Поэтому
сохраняются пустые файлы, нулевые байты, UTF-8 и произвольные двоичные данные.

Формат контейнера: 8 байт ASCII `AES128C1` (включает версию 1), 16 байт IV,
затем непустая последовательность 16-байтовых шифроблоков. Неверный заголовок,
длина и padding отвергаются. Один и тот же файл обычно получает разные
шифртексты из-за нового IV. Ключ — ровно 32 шестнадцатеричных символа;
пароли не преобразуются в ключ автоматически.
